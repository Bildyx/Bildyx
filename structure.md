# Bildyx

## Overview
Job/career reference platform (industries, countries, cities, jobs, organizations, skills, etc.) with a marketing website and a backend API.

## Tech Stack
- **Language**: TypeScript (backend), PHP/HTML (website)
- **Framework**: Express (API), Prisma (schema/migrations only)
- **Key dependencies**: Kysely (actual query builder, using `apps/api/src/db/types.ts` generated by kysely-codegen), Zod (API validation), pg
- **Build / runtime**: npm workspaces (root `package.json`), tsx

## Project Structure
```
apps/
├── api/                  # Backend API (Express + Kysely + Prisma schema)
│   ├── prisma/
│   │   └── schema.prisma # Source of truth for DB schema (Prisma migrations)
│   ├── src/
│   │   ├── db/types.ts   # Kysely types generated from live DB (kysely-codegen) — can drift from schema.prisma if migrations aren't regenerated
│   │   ├── models/        # Zod schemas per resource, field names match snake_case DB columns
│   │   └── routes/        # Express routes per resource
│   ├── scripts/
│   │   ├── generate_excel_templates.py  # Generates .xlsx import templates from schema.prisma
│   │   └── excel_to_csv.py              # Converts apps/api/data/excel/*.xlsx into apps/api/data/*.csv
│   └── data/
│       ├── *.csv                 # Legacy/manual data exports + CSVs generated from data/excel
│       ├── excel/                 # Filled-in .xlsx data files (converted to CSV via excel_to_csv.py)
│       └── excel_templates/      # Generated .xlsx templates (one per reference model)
└── website/               # Marketing site (PHP/HTML/CSS/JS)
Files/                      # Legacy hand-curated business data templates (csv/excel), unrelated to DB schema column names
```

## Key Files
| File | Role |
|------|------|
| `apps/api/prisma/schema.prisma` | Prisma schema — canonical model/field definitions |
| `apps/api/src/db/types.ts` | Kysely DB types (generated, may be stale vs. schema.prisma) |
| `apps/api/src/database.ts` | Kysely instance setup (Postgres/PGlite) |
| `apps/api/scripts/generate_excel_templates.py` | Parses schema.prisma and emits one Excel template per reference-data model |

## Architecture Notes
- The API layer uses **Kysely**, not Prisma Client, for queries. Prisma is used only for schema/migrations. Field names used in code (`models/*.ts`, `db/types.ts`) are DB column names (snake_case via `@map`/`@@map`), not the Prisma camelCase model field names.
- `Country.officialLanguages`, `Organization.numberOfEmployees`, and `Organization.numberOfSubsidiaries` intentionally have no `@map` in `schema.prisma` — confirmed via the applied migration SQL (`apps/api/prisma/migrations/20260702062228_init/migration.sql:97,195-196`) that the real DB columns are camelCase (quoted), matching `schema.prisma` and `db/types.ts` as-is. The snake_case headers for these fields in `apps/api/data/*_rows.csv` are from a manually reformatted export, not the real column names — don't use those CSVs as a naming reference.
- Models considered "reference data" (not tied to site auth/job-ad workflow): Industry, Country, City, Job, Organization, Skill, Certification, University, StudyFields, MilitaryCapabilities, Degree. These are the ones covered by `generate_excel_templates.py`. Excluded: JobAd, JobAdSkill, User, UserSession, UserProfile, UserCertifications, UserEducations, UserEducationFields, AuditLog, Subject.
