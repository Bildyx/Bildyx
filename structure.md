# Bildyx

## Overview
Job/career reference platform (industries, countries, cities, jobs, organizations, skills, etc.) with a marketing website and a backend API.

## Tech Stack
- **Language**: TypeScript (backend), PHP/HTML (website)
- **Framework**: Express (API), Prisma (schema/migrations only)
- **Key dependencies**: Kysely (actual query builder, using `apps/api/src/db/types.ts` generated by kysely-codegen), Zod (API validation), pg
- **Build / runtime**: npm workspaces (root `package.json`), tsx

## Project Structure
```
apps/
├── api/                  # Backend API (Express + Kysely + Prisma schema)
│   ├── prisma/
│   │   └── schema.prisma # Source of truth for DB schema (Prisma migrations)
│   ├── src/
│   │   ├── db/types.ts   # Kysely types generated from live DB (kysely-codegen) — can drift from schema.prisma if migrations aren't regenerated
│   │   ├── models/        # Zod schemas per resource, field names match snake_case DB columns
│   │   └── routes/        # Express routes per resource
│   ├── scripts/
│   │   ├── generate_excel_templates.py  # Generates .xlsx import templates from schema.prisma; also locks them down (see below)
│   │   └── excel_to_csv.py              # Converts apps/api/data/excel_templates/*.xlsx into apps/api/data/*.csv (skips fully blank rows)
│   └── data/
│       ├── *.csv                 # CSVs generated from data/excel_templates via excel_to_csv.py
│       └── excel_templates/      # Generated .xlsx templates (one per reference model) — also doubles as the filled-in working data file (excel_to_csv.py reads from here, not a separate data/excel/)
└── website/               # Marketing site (PHP/HTML/CSS/JS)
Files/                      # Legacy hand-curated business data templates (csv/excel), unrelated to DB schema column names
```

## Key Files
| File | Role |
|------|------|
| `apps/api/prisma/schema.prisma` | Prisma schema — canonical model/field definitions |
| `apps/api/src/db/types.ts` | Kysely DB types (generated, may be stale vs. schema.prisma) |
| `apps/api/src/database.ts` | Kysely instance setup (Postgres/PGlite) |
| `apps/api/scripts/generate_excel_templates.py` | Parses schema.prisma and emits one Excel template per reference-data model |

## Architecture Notes
- The API layer uses **Kysely**, not Prisma Client, for queries. Prisma is used only for schema/migrations. Field names used in code (`models/*.ts`, `db/types.ts`) are DB column names (snake_case via `@map`/`@@map`), not the Prisma camelCase model field names.
- `Country.officialLanguages`, `Organization.numberOfEmployees`, and `Organization.numberOfSubsidiaries` intentionally have no `@map` in `schema.prisma` — confirmed via the applied migration SQL (`apps/api/prisma/migrations/20260708013135_init/migration.sql`) that the real DB columns are camelCase (quoted), matching `schema.prisma` and `db/types.ts` as-is. `organizations.csv`'s header uses the same camelCase for these two columns; the seed script reads them accordingly. The snake_case headers for these fields in `apps/api/data/*_rows.csv` are from a manually reformatted export, not the real column names — don't use those CSVs as a naming reference.
- Every FK field that logically points at an auto-generated UUID (`City.id`, `Organization.id`) must be resolved from the CSV's human-readable name via a DB lookup in the seed script (see `buildNameLookup` in `apps/api/prisma/seed-utils.ts`, used by `seeds_universities.ts`/`seeds_certifications.ts`/`seeds_subjects.ts`/`seeds_military_capabilities.ts`) — the CSVs can't contain the real UUID since it doesn't exist until insertion. This does **not** apply to `Country`, since `Country.isoCode` is a stable natural key (2-letter code) known ahead of time; `City.countryId`/`University.countryId`/etc. reference it directly as `@db.Char(2)`, no lookup needed.
- Models considered "reference data" (not tied to site auth/job-ad workflow): Industry, Country, City, Job, Organization, Skill, Certification, University, StudyFields, MilitaryCapabilities, Degree, Subject. These are the ones covered by `generate_excel_templates.py`. Excluded: JobAd, JobAdSkill, User, UserSession, UserProfile, UserCertifications, UserEducations, UserEducationFields, AuditLog.

## Recent Changes
- [2026-07-14] Locked down `apps/api/data/excel_templates/*.xlsx` against import errors, with zero data loss (verified cell-by-cell against the pre-change files). `generate_excel_templates.py`: added a `--protect-existing` mode that adds protection/validation to already-filled templates in place (data untouched) — reruns safely (clears old validations first instead of stacking duplicates). Every column now gets a type-matching Excel data validation with an English error message (`whole`/`decimal`/`date`/`TRUE,FALSE` list, or an enum dropdown), the header row and any column outside the defined fields are locked via `ws.protection.sheet`, and `wb.security.lockStructure` blocks adding/renaming/deleting sheets. **Only the set of columns is restricted, not the number of rows** — some of these are filled to 100k+ rows, so unlocking/validation is applied at the Excel column level (`ws.column_dimensions[col].protection`/data-validation `sqref` up to row 1,048,576), which Excel applies as that column's default style for every row without creating a per-row cell object, rather than looping over a capped row range. Existing filled rows in `--protect-existing` mode are additionally unlocked cell-by-cell (bounded by the file's real current size, so still cheap) since already-styled cells override the column default. No password was set on either protection (guardrail against accidental input errors, not a security barrier — team can unprotect via Excel's UI if a template needs a real structural edit). Enum dropdowns are now sourced from a `veryHidden` `_lists` helper sheet (range reference) instead of an inline comma string, which also fixes a pre-existing bug where large enums (e.g. `Currency`, ~154 values) silently lost their dropdown on openpyxl resave (Excel's inline-list validation has a 255-character cap; a range reference doesn't). `excel_to_csv.py` now skips fully-blank rows (defensive, in case of stray touched-but-empty rows).
